# API стереотрекинга и проекции

Служба отдаёт интерфейс AR-роя в `/swarm/`. HTTP по умолчанию слушает порт **8765**, WebSocket — **8766**. Оба порта задаются отдельно. Фактические адреса потоков публикуются в состоянии службы. На сайте карта глубины и маркеры обновляются независимо.

## Карты и состояние

| Запрос | Ответ |
|---|---|
| `GET /api/v1/state` | Калибровки, координаты рабочего поля, настройки поверхности, последний снимок, показатели и адреса потоков |
| `GET /api/v1/depth.png` | Уменьшенный полупрозрачный слой глубины для поля роботов |
| `GET /api/v1/preview.jpg` | JPEG растра, отправленного в окно физического проектора |
| `GET /api/v1/markers` | Метки ArUco и состояние стереокамер |
| `GET /api/v1/projection` | Настройки физического вывода и доступные режимы |
| `GET /status` и `GET /frame.jpg` | Совместимость со старым просмотрщиком. `/frame.jpg` возвращает цветную карту в координатах выпрямленной камеры |

В `state.projection` поля `width` и `height` описывают **калиброванный растр целиком**. `available_rect` — прямоугольник `[left, top, right, bottom]` в пикселях этого растра, с исключённой правой и нижней границами. Начало координат находится в верхнем левом углу, X направлена вправо, Y вниз. Метки и PNG используют это пространство. Например, PNG размером 480 × 300 следует отрисовать на всём поле 1280 × 800 с тем же преобразованием, что применяется к маркерам. Если в интерфейсе показывается только рабочая область, обрезайте уже размещённый слой по `available_rect`.

PNG содержит приглушённые оттенки рельефа и препятствия. Пропуски и область за пределами маски прозрачны. Для сайта растр пропорционально уменьшается до габаритов 480 × 320 пикселей. Проектор получает цветное представление той же поверхности с применением калибровки пола, геометрии рабочей области и 3D-модели проектора. При `above_range: "black"` поверхности выше верхней границы на проекторе чёрные. В режиме привязки к плоскости применяется калиброванная гомография. При удержании неподвижной сцены используется последний снимок.

`stage` показывает состояние калибровок: `stereo_required`, `floor_required`, `projector_required` или `ready`. Наличие видеосигнала проверяется по `tracking.cameras`. `snapshot` равен `null` до первого JPEG. Далее снимок содержит `id`, `age_s`, `projection_revision`, `settings_revision` и флаг `depth_ready`. В `metrics` доступны частота проверок `check_hz`, число публикаций `update_count`, доли измеренных и заполненных участков `measured_fraction` и `filled_fraction`. Режим карты высот также сообщает `noise_mm`. `capture_time_unix_ms` указывает время получения исходной стереопары для карты.

Оба запроса изображений возвращают `503`, если соответствующий растр ещё не готов. Успешный ответ содержит заголовки `X-Snapshot-Id`, `X-Projection-Revision` и `X-Settings-Revision`. PNG и JPEG одного снимка имеют одинаковые идентификаторы и ревизии. HTTP отдаёт **последний** кадр, поэтому он может быть новее уведомления WebSocket. Используйте идентификатор фактически полученного ответа и учитывайте, что номера могут пропускаться. После смены `projection_revision` загрузите геометрию из состояния заново.

## Независимые потоки WebSocket

Если `state.streams` содержит объект, подключитесь по указанному порту к двум маршрутам. Например, для той же машины при порте 8766 адрес первого потока будет `ws://127.0.0.1:8766/ws/depth`.

| Поток | Сообщение JSON |
|---|---|
| `/ws/depth` | `{"snapshot_id":42,"projection_revision":"local-…"}`. При смене пары значений загрузите PNG одним HTTP-запросом. Ноль означает, что слой глубины недоступен |
| `/ws/markers` | Тот же объект, что и в ответе `GET /api/v1/markers` |

Соединения предназначены для чтения. Служба отправляет текущее состояние при подключении, последующие изменения и периодические повторные сообщения. Если `streams` равен `null` или WebSocket недоступен, опрашивайте `/api/v1/state` и `/api/v1/markers` независимо, а PNG загружайте только при изменении снимка. В состоянии подсказки об ошибке запуска потоков доступны в `errors`.

Дополнительный origin для чтения нового API и подписки на потоки указывается через `--lan-preview-origin`. Изменение настроек физического вывода через `POST /api/v1/projection` доступно странице с origin самой службы.

## Метки ArUco

Корневой ответ содержит `schema_version`, `frame_id`, `captured_at_unix_ms`, `age_s`, `projection`, `markers` и, при включённом трекинге, `tracking`. До получения пары время и возраст равны `null`. `frame_id` может измениться при обновлении статуса пропуска, тогда время последней полученной пары сохраняется.

| Поле метки | Значение |
|---|---|
| `id` | Номер 0–5 из словаря `DICT_4X4_50` |
| `x`, `y` | Центр метки в пикселях калиброванного растра проектора |
| `angle` | Направление центра к верхней грани метки, в радианах от +X по часовой стрелке |
| `position_m` | Центр `[X,Y,Z]` в метрах в `rectified_left` |
| `rotation` | Матрица 3 × 3 из системы метки в `rectified_left`, записанная строками. Система указана в `coordinate_space` |
| `visible` | Признак свежей принятой стереопозы. Для потерянной метки координаты относятся к последнему обнаружению |
| `last_seen_unix_ms` | Время последнего принятого измерения метки в миллисекундах Unix |
| `quality` | `reprojection_rms_px` и `epipolar_rms_px` в пикселях снимка, `side_error_mm` в миллиметрах, `min_side_px` в пикселях и оценка `score` от 0 до 1 |

Поза оценивается по двум выпрямленным изображениям и сглаживается в метрах и в 3D-ориентации. Независимый цикл собирает пары примерно раз в секунду. Между измерениями возможны короткие пропуски. Сайт добавляет точки траектории только для `visible:true` и скрывает просроченные позы. Возраст конкретной позы можно получить из `age_s` и неотрицательной разницы `captured_at_unix_ms - last_seen_unix_ms`, переведённой в секунды. Такой расчёт использует часы службы.

`tracking.cameras` содержит две записи в порядке «левая, правая» с `index`, `ready`, `fps` и `error`. `pair_skew_ms` показывает разницу времени **получения** кадров пары и равен `null` без актуальной пары. Допустимый порог находится в `max_skew_ms`. При наличии данных `capture_size` сообщает размер пары ArUco, `sample_interval_s` — интервал независимого цикла, `capture_profile` — результат выбора режима захвата.

## Настройки физического вывода

`GET /api/v1/projection` возвращает `controllable`, номер `revision`, текущие `settings`, доступные `modes` и список `displays`. В `calibration` указаны размеры исходного растра и полоса шумоподавления `noise_mm`. `presentation_error` содержит подсказку при несовместимом исходном режиме. В списке `displays[].modes` перечислены режимы, объявленные Windows и совместимые по пропорциям с калибровкой. При оконном выводе можно использовать размер калибровки. Полноэкранная смена разрешения применяется к выбранному дисплею временно. При штатной остановке служба восстанавливает предыдущий режим.

`POST /api/v1/projection` принимает полный JSON-объект с `expected_revision` из свежего GET:

```json
{
  "expected_revision": 0,
  "display": "\\\\.\\DISPLAY2",
  "width": 1280,
  "height": 800,
  "fullscreen": true,
  "appearance": "smooth",
  "fill": "surface"
}
```

Используйте идентификатор из `displays[].id` и поддерживаемые им размеры. `appearance` выбирается из `raw`, `balanced`, `smooth` и соответствует клавише **S**. `fill` выбирается из `conservative`, `surface` и соответствует **F**. Ответ при успехе содержит то же состояние, что GET. `409` означает конфликт ревизий, `400` — ошибку параметров, `403` — сторонний origin, `501` — режим без контроллера проектора, `503` — временную недоступность. Ошибки настроек передаются в `error.message`. Настройки физического вывода имеют свою ревизию, отдельно от диапазона высот и маски поверхности.

## Диапазон высот, маска поверхности и сканирование

Совместимый `POST /api/v1/settings` в режиме калиброванной проекции принимает **все** поля настройки. Возьмите `projection_revision` и `settings_revision` из `GET /api/v1/state`. Передайте второе значение как `expected_settings_revision`.

```json
{
  "schema_version": 1,
  "request_id": "scene-17",
  "projection_revision": "local-…",
  "expected_settings_revision": 0,
  "height_range_m": [0.0, 0.5],
  "above_range": "black",
  "palette_gamma": 0.5,
  "update_interval_s": 1.0,
  "roi": {
    "coordinate_space": "projector_normalized",
    "vertices": [[0.25, 0.15], [0.75, 0.15], [0.75, 0.85], [0.25, 0.85]]
  }
}
```

API принимает `0 ≤ min < max ≤ 0,50` м, гамму от 0,1 до 3 и минимальный интервал публикации от 0,5 до 10 секунд. Верхняя граница должна быть выше полосы шумоподавления. При обычном запуске полоса у нуля составляет 15 мм. Она задаётся параметром службы `--height-noise-mm` и сохраняется при изменении диапазона и палитры через HTTP.

ROI — простой полигон из 3–32 различных вершин внутри `available_rect`, с ненулевой площадью. Допускаются вогнутые формы. Координаты нормализуются относительно **полного** растра как `x / width` и `y / height`. Указанная в примере область подходит только при подходящих границах поля. Маска сохраняет положение геометрии. Снаружи проекция чёрная, веб-слой прозрачен.

При успехе возвращаются `request_id`, принятая `settings_revision` и текущий `snapshot_id`. Применение к кадру подтверждается совпадением `state.snapshot.settings_revision` с принятой ревизией. Служба перерисовывает последний измеренный снимок с новыми настройками. При `409` получите свежие ревизии, при `400` исправьте данные запроса.

`POST /api/v1/actions/rescan` с `projection_revision` из состояния и необязательным `request_id` запрашивает повторную обработку поверхности в режиме проекции. Ответ `accepted:true` с `action_id` подтверждает принятие запроса. Следующий опубликованный снимок отслеживается обычным способом. `POST /api/v1/actions/calibrate-floor` возвращает `501`. Калибровка пола выполняется локальным инструментом.
