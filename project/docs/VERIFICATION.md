# Проверка AR-роя

Проверено 24 ноября 2026 года в Windows с Python 3.10 x64 и OpenCV 4.14 с оконным выводом WIN32. Для цифровых проверок использованы тестовые стереопары, включая кадры 1920×1080 с метками 50 мм, и сохранённые записи глубины проекта. Калибровочные файлы рабочей установки сверены с резервным архивом по SHA-256. Все 226 файлов в каталогах калибровок совпали.

| № | Пункт | Результат |
| --- | --- | --- |
| 1 | Запуск приложения | Нативное окно открылось в чистом окружении. HTTP и оба канала WebSocket запустились. Настройки проектора, существующий API настроек и повторное построение карты приняли запросы. Процесс штатно завершился |
| 2 | Обе камеры | **Нужна проверка оборудования.** Вход `#0` даёт 1280×720 около 30 кадров/с. DirectShow не открывает `#1`. Согласованный размер выше 1280×720 физически не подтверждён |
| 3 | Карта глубины | Реальный алгоритм SGBM построил карту на тестовой стереопаре во время комбинированного запуска. Тесты с сохранёнными картами проверили шум и обновление при движении. Для новой живой карты этой установки нужны оба входа |
| 4 | Геометрия физического вывода | Цифровой рендер прошёл проверки рамки, пропорций, перекрытия препятствиями и маски рабочей зоны. На проверяемом ПК Windows не подтвердила смену на 16:10 через `CDS_TEST`. Проверка совмещения света на рабочей поверхности остаётся открытой |
| 5 | Шумоподавление 15 мм | Тест проверил базовый цвет пола в нейтральной полосе, изменение цвета выше неё и исключение объектов выше 50 см. Нативная служба сообщила 15 мм через API |
| 6 | Клавиши S и F | События клавиш прошли через штатный цикл OpenCV на тестовой паре. Каждое переключение опубликовало новый результат из сохранённого кадра. Смена оформления и заполнения через HTTP также проверена |
| 7 | ID 0–5 в высоком разрешении | Все шесть ID распознаны на тестовых кадрах 1920×1080. Проверены геометрия маркера, ошибки репроекции, отсутствие одной камеры, временная потеря и сглаживание угла. Максимальный режим реальных камер нужно подтвердить при подключении |
| 8 | Глубина во время ArUco | В общем запуске тестовая последовательность продолжала проходить через SGBM и 3D-рендер, пока отдельный поток обрабатывал высокоразрешённые пары ArUco. Переключение S/F не останавливало этот поток |
| 9 | Поза, ориентация и статус на сайте | В Chrome проверены координаты, ориентация, качество, пунктирная потерянная метка, время последнего обнаружения и состояние камер. Проверены оба WebSocket и резервный HTTP |
| 10 | Минималистичная веб-карта | Chrome получил PNG 480×300 с прозрачными границами и наложил его под роботов в координатах растра 1280×800. PNG и проекторный JPEG имели один идентификатор снимка. Пока снимок не менялся, повторных загрузок PNG не было |
| 11 | Следы движения | В Chrome проверены история по измеренным координатам, цвет, направление, затухание и отдельное отключение следов |
| 12 | Задержка и FPS | При искусственно занятом кодировщике проверена замена ожидающего кадра последним без накопления очереди. На плотной тестовой карте 640×360 медиана 3D-рендера была около 0,87 с для проектора и 0,88 с вместе с компактным слоем. Эти измерения относятся к рендеру в тесте. FPS и задержку подключённой стереоустановки ещё нужно измерить |

## Повтор автоматических проверок

Из корня распакованного проекта:

```powershell
.\setup.cmd
Push-Location project
..\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
Pop-Location
```

Комбинированный тест находится в [test_synced_pipeline.py](../tests/test_synced_pipeline.py). Он получает тестовую 1080p-пару на входе камеры, выполняет реальные OpenCV, стереопоиск и распознавание меток, проверяет публикуемые растры и посылает S/F в основной цикл. Оптическое совмещение на поверхности проверяется после подключения оборудования.
